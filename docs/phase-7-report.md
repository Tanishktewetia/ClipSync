## What was built

- Native Windows DNS-SD (_clipsync._tcp), with a resolvable computer hostname; Android parallel hotspot/saved-IP/manual-IP/NSD candidate probing over Wi-Fi, retaining pinned mTLS trust.
- Network-triggered recovery; 1/2/5/15/30-second capped backoff; negotiated 15-second heartbeat with two missed replies retiring the session.
- Memory-only newest-known-text reconciliation, Lamport ordering, cross-language STATE/PONG extension, replay opt-out on Android and Windows, explicit offline phone send capture, failed clipboard-apply retry support.
- Android 0.7.0 (versionCode 8): status-first home, Find & pair my PC flow without mandatory IP, loading spinner/progress, visible tile shortcut explanation, full offline Guide, pairing/setup/background/privacy/troubleshooting instructions, GitHub/issues links. Manual IP and Diagnostics remain Advanced. Guide supports system Back and an RTL-aware back icon.
- SaaS-style landing site and full documentation: responsive light/dark layouts, product illustration, download CTA, setup steps, feature sections, FAQ, privacy, GitHub links, real APK download and SHA-256 checksum. No analytics or external font requests.
- Root README and documentation index corrected: phone sending is deliberate, not zero-tap; no USB or developer-mode prerequisites.

No new runtime/application package dependencies. Native Windows DNS APIs and Android NSD are used. Website runtime/build use HTML/CSS/JS and Node built-ins. Existing bundled Playwright/Chrome was used for local browser verification, not added as an application dependency.

## Design note

UI/UX Pro Max research and frontend-design guidance informed the layout. The Android app keeps indigo/lavender identity, semantic green/amber/violet/red status feedback, Material 3 cards, generous touch targets and light/dark themes. A visible Guide and a dedicated send-shortcut card replace buried instructions. The website extends the same brand onto a warm neutral canvas, oversized editorial headline, dark device-demo panel, teal detail accents and a clear download-to-setup hierarchy. It intentionally resembles a polished SaaS product page without inventing subscriptions, testimonials, customer counts or cloud features. The product visual is labelled as an illustration, not a real phone screenshot.

## Exact manual acceptance steps — no USB

1. **Install matching builds.** Quit the old Windows tray process. Launch the Phase 7 Windows executable above. Send the 0.7.0 APK to Telegram Saved Messages, save/open it on the phone and install over the existing app. Expected: both apps show 0.7.0; existing pairing is retained. Do not uninstall unless deliberately testing a fresh identity.
2. **Router, no IP typing.** Put both devices on the same private router Wi-Fi. On Android open Advanced, clear Manual PC IP and tap Connect/Find my PC. Expected: existing pinned PC reconnects without a new pairing prompt. If genuinely unpaired, choose Pair new device on Windows and Find & pair my PC on Android; confirm only matching six-digit codes.
3. **Re-pairing guide.** Read Android Guide → Connect your devices and return using the back button/gesture. Expected: plain-language steps, no Developer options/helper-app instruction, and Back returns to the status screen rather than closing the app.
4. **Automatic PC → phone.** Leave Android unlocked, copy three different non-sensitive test texts on Windows, then paste after each on the phone. Expected: latest text arrives without a Receive tap, no echo loop. An OS clipboard indicator may appear; its preview should be redacted.
5. **Tile education/setup.** Tap What is a tile? Show me how. Follow Add Send to PC, or swipe down twice → pencil/Edit → drag Send to PC into active tiles → Done. Expected: the guide explains tiles beside Wi-Fi/Bluetooth; the shortcut is visible and usable.
6. **Manual phone → PC.** Copy text in a different phone app. First do not tap anything: expected no send. Then tap the tile, paste on Windows, repeat using the notification action. Expected: each explicit tap sends once and returns to the source app.
7. **Wi-Fi and data transition.** With both apps enabled, turn phone Wi-Fi off for 20 seconds, leave mobile data on, then restore Wi-Fi. Expected: no mobile-data clipboard connection; automatic recovery over Wi-Fi with no IP entry/re-pair. Failed searches include their own timeout plus capped retry delay.
8. **PC restart.** Quit only Windows ClipSync, wait for Android to notice, then start the Phase 7 Windows build again. Expected: Android reconnects automatically; pin remains valid. Do not open a fresh pairing window for normal reconnect.
9. **Out-of-range return.** Leave Wi-Fi range long enough to drop the link, then return. Expected: connection retires/retries and recovers automatically. A silent half-open link is detected around two 15-second heartbeat intervals when the OS does not signal loss earlier.
10. **Hotspot, no typing.** Enable the Windows hotspot manually (this phase does not manage it), join it on the phone, leave Manual PC IP empty. Expected: connection to the paired PC via the actual hotspot gateway or NSD with no re-pair. Return to router Wi-Fi and check recovery again.
11. **Newest offline PC text.** Keep both processes running. Turn phone Wi-Fi off, copy three different texts on Windows, restore Wi-Fi, paste on Android. Expected: only the newest retained PC text is applied, not a queue of historical clips.
12. **Explicit offline phone text.** Disconnect Wi-Fi while the enabled phone service stays running. Copy text and tap Send to PC; repeat with newer text and tap again. Reconnect without copying on Windows during this test. Expected: only the last deliberately captured phone text reconciles to Windows. A phone copy without tapping is not known and must not be silently read.
13. **Opt-out and live updates.** Disable Apply latest text on reconnect in Android Advanced. Disconnect, copy on Windows, reconnect: expected no initial overwrite on Android. Make a new Windows copy after Connected: expected normal delivery. Repeat the mirror test with the Windows tray preference and explicit offline phone sends. Re-enable both afterward.
14. **Pause/close/lock.** Pause and copy in either direction: expected no application. Resume, close/swipe away only the Android UI, then verify sharing still works. Lock the phone, copy twice on Windows, unlock and paste: expected latest deferred text. Opening the UI is not required for normal unlocked delivery.
15. **Reboot.** With sync enabled, restart the phone, unlock once and wait. Expected: notification/service recovery request, automatic pinned reconnect when Windows is available. A deliberate Android force-stop is different and requires reopening the app. Pending text does not survive reboot.
16. **Android visual check.** Review Connected/Waiting/Paused/Error, search loading animation, six-digit pairing, Guide, tile help, Advanced and Diagnostics in light/dark mode and with larger text size. Expected: readable layouts, no clipped buttons, reachable documentation and GitHub links. Send screenshots if any screen still feels unfinished.
17. **Website.** On the PC open http://127.0.0.1:4177. Test theme toggle, setup/docs, FAQ, GitHub and Download Android APK. Expected: an actual 0.7.0 APK and working documentation, with beta limitations visible. To use the site on the phone, intentionally start a separate LAN preview on a different port, for example set PORT=4178 and run node site/serve.cjs --lan, then visit http://<PC-WiFi-IP>:4178. Allow only the intended private-network firewall prompt; stop it after testing.
18. **Stop is respected.** Tap Stop background connection, close/reopen the screen and reboot if desired. Expected: enabled recovery stays off until you explicitly connect again.
